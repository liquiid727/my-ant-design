# ADR-0004 · 第二个品牌包：白标，而不是第二个产品

**状态**：已采纳（M1 验收）

## 背景

"管线与骑行无关"需要一个可执行的判据。选择做**第二个品牌包**（`ledger/`：冷白 + 砖红 + 无衬线 + 小圆角），
而不是做第二个完整产品：

- 成本差一个数量级：品牌包是四五十行 JSON，第二个产品要重写页面与产品语义；
- 它检验的正是最容易被写死的东西：颜色、字体、圆角、阴影、缓动；
- 页面结构完全不动，`pipeline.config.mjs` 只加一个条目。

## 决定

- 品牌包 = 视觉身份，只允许覆盖白名单：`brand.palette` / `color.{brand,surface,ink,action,border}` /
  `radius.*` / `type.{display,title,metric}.*` / `elevation.*` / `motion.easing.*`。
- 产品语义（`route.*` / `achievement.*` / `postcard.*`）留在产品侧，但**引用品牌意图**而不是原始色阶：
  `route.primary → {color.action.primary}`、`postcard.stamp → {color.brand.mark}`。
  这样白标时产品会跟着品牌走，而不是各个品牌各留一套骑行配色。
- 结果：4 套排列（2 品牌 × 2 主题），60 组对比度配对全部达标，组件与页面零改动。

## 发现（比结论更重要）

1. **白名单第一次不够用**：边框色必须能跟着表面走，否则冷白卡面配暖灰描边。已把 `color.border` 加进白名单。
2. **密度故意留在 core**：品牌不能改 `space.*`。否则同一个 `Metric` 在不同品牌下的高度不可比，
   视觉回归也无从对比。要支持紧凑/宽松，应该做成独立的 `density` 轴，而不是塞进品牌包。
3. **产品语义引用品牌意图**，是白标能成立的关键。引用 `{color.ramp.*}` 会把产品锁死在某个品牌的原始色阶上。
4. **白标 ≠ 跨产品**。ledger 仍然使用骑行产品的语义（路线/成就/明信片）。真要做第二个产品，
   需要把 `product` 从品牌里拆成独立的 `app` 层：`app × brand × theme`。这是下一步，配置已经预留了位置。

## 后果

- 好处：通用性有了可执行证据；白标场景（同一产品多渠道）可以直接复用。
- 代价：`tokens.css` 从 10.7 KB 涨到 21 KB（多一套品牌块 + 深色块），可接受；
  排列继续线性增长时，需要按品牌拆分产物文件。
